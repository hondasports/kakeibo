# 要求を固める

## 入力・起動

元の依頼と関連source/testを調べ、目的・対象範囲・受入条件・維持条件・検証方法・完了地点を定める。期待結果は外から観測できる形にする。

## 判断と出力

結果を左右する未解決事項は安く調査して解消し、残る選択だけ質問する。境界・拒否・失敗・永続化・caller・並行実行・UI状態を必要な範囲で考え、該当する要求と確認方法だけ残す。

受入条件は外から観測できるbulletに構造化してIssue・PR本文へ残し、完了時に全件照合できる形にする。完了地点（local_verified / pr_created / merge_ready相当）を明示する。
