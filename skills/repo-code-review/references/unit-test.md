# ユニットテスト確認点

カバレッジ率は判定に使わない（`scripts/run-coverage.mjs` の閾値は参考値）。変更した振る舞いにテストがあるかで判定する。

## 変更とテストの対応表

変更した関数・分岐ごとに作り、レビュー結果の末尾に付ける。

```text
| 変更箇所 | 振る舞い | テスト | 判定 |
| convex/foo.ts:bar | 別グループは拒否 | convex/foo.test.ts「別グループ…」 | OK |
| src/features/x/y.ts:z | 0円の扱い | なし | 要追加 |
```

## 確認点

- 認証・グループ境界・権限がある操作では、それぞれの許可・拒否を適切なサーバー側テストで確認しているか。公開データや境界のないinternal関数へ同じケースを一律に要求しない
- 境界値: 金額0・端数、混在税率、週・月の境界、空配列
- テストは実装ファイルと同じディレクトリに置いているか（`src/`・`convex/`・`lib/`・`tests/` の既存規約）
- 「例外が出ない」だけのテストや、モック自体を検証しているだけのテストがないか
- バグ修正には、修正前に失敗する回帰テストがあるか（実装側の手順は `skills/implementation`）

## 差分カバレッジの手動確認

対応表で判断できないときだけ行う。

1. `pnpm test:coverage` を実行する（出力先は `coverage/overall/`）
2. `git diff -U0 origin/preview...HEAD` で変更行を取り出す
3. `coverage/overall/coverage-final.json` の該当ファイルで、変更行の実行回数が0の行を確認する

未カバー行があれば、テスト追加か、テスト不要の理由を所見に残す。
